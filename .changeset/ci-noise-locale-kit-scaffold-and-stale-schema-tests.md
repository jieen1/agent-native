Fixed two real, distinct CI failures that had been treated as unrelated "pre-existing noise" bypassed on every merge (SDLC-096 CI-noise cleanup):

1. **Scaffold bug**: every template's `actions/change-language.ts` imports `locale-kit/action`, but `locale-kit` is a private, never-published `workspace:*` package. The standalone scaffold path (`agent-native create <name> --standalone --template <t>`) blindly rewrote every `workspace:*` dependency it didn't specifically recognize to `"latest"`, so a fresh standalone app's `pnpm install` either failed to resolve `locale-kit` or could have resolved an unrelated public npm package of the same name. Fixed by vendoring `locale-kit` (and any other per-template required package) into `packages/<name>` for standalone scaffolds via the same mechanism already used for workspace scaffolds (`scaffoldRequiredPackages`), declaring the scaffold as a minimal (app root + `packages/*`) pnpm workspace, and leaving those specific dependencies as `workspace:*` so they link locally instead of being rewritten. Also fixed a related gap where a vendored package's own `catalog:`-referenced devDependencies (e.g. `react`, `vite`) had nothing to resolve against outside the monorepo's catalog. Verified end-to-end: real scaffold → `pnpm install` → `pnpm typecheck` → dev server boot → HTTP 200 page load, with no `locale-kit` resolution error.
2. **Stale tests**: `tool-schemas.spec.ts` and `coding-tools/index.spec.ts` asserted a top-level `oneOf` combinator on the `db-exec` tool schema that a documented, intentional prior fix (CORE-PATCHES.md #3 — the Anthropic Messages API rejects any tool schema with a top-level `oneOf`/`allOf`/`anyOf`) had already removed. The either-`sql`-or-`statements` exclusivity is real and still enforced at `run()` time; the tests were simply never updated after that fix landed. Updated both to assert the schema's actual, intentional shape.
